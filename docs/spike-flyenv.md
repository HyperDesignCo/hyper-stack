# Spike: FlyEnv as the Hyper Stack runtime

Status: desk research only (docs and source read over HTTP). Nothing was installed or run on a real machine.
Items marked **UNVERIFIED** need a hands-on check on a clean Windows box and a clean Mac before we rely on them.

## Summary / recommendation

**Choose (ب): a direct Runtime.** FlyEnv stays optional.

Reasons, strongest first:

1. **Site limit.** In `src/fork/module/Host/index.ts`, `handleHost` blocks `add` when `isLock` is true. Without a license the lock applies once more than two hosts exist. A license is checked against `machineId()`. An agency running many projects would hit this at the third site. Verify on a real install (UNVERIFIED), but it alone makes (أ) risky.
2. **No supported control surface.** The README documents no CLI and no REST API. The only programmatic interface is the built-in MCP server (below), which needs the Electron GUI running.
3. **Moving target.** Internals are Electron/Node, with a Go privileged helper that is still being migrated (the Node helper is deprecated). Data directory is still named `PhpWebStudy`. Driving it from outside means depending on undocumented behavior.
4. **Missing pieces.** None of the 18 MCP tools covers hosts file, certificates, or per-project PHP-FPM processes. We would still build most of the system ourselves.

## Answers to the five questions

### 1. How does FlyEnv install services, and where are binaries?
- Native binaries, no containers. Each service has a module in `src/fork/module/<Service>` with `installSoft()`, `fetchAllOnlineVersion()`, `_startServer(version)`, `_stopService(version)`.
- macOS data dir: `~/Library/PhpWebStudy` (seen in the repo's `.flyenv`, e.g. `~/Library/PhpWebStudy/app/nodejs/v24.1.0`). Windows path: **UNVERIFIED**.
- Exact download sources for PHP/MySQL/Nginx builds: **UNVERIFIED**.

### 2. Programmatic control?
- No documented CLI or REST API.
- MCP server: Streamable HTTP on `127.0.0.1:7682` by default (configurable, 1024-65535), Bearer token auth. Runs in the app's main process, so **it exists only while the GUI is running** and must be enabled by the user. Action tools default to a confirm policy. Tools (names only, descriptions inferred): `list_services`, `service_status`, `list_sites`, `resolve_site_runtime`, `resolve_site_urls`, `get_database_connection_info`, `get_service_exec_info`, `get_managed_file_map`, `list_log_files`, `list_config_files`, `list_online_versions`, `start_service`, `stop_service`, `restart_service`, `create_site`, `update_site`, `delete_site`, `install_service`.
- Whether `install_service` covers PHP/MySQL: **UNVERIFIED**.

### 3. Vhosts and local domains
- Per-site configs are generated by `makeNginxConf` (and Apache/Caddy/FrankenPHP equivalents) into `vhost/nginx/<host.id>.conf` under the data dir. Edits regenerate either incrementally (`_editVhost`) or fully (`_delVhost` then `_addVhost`).
- Where FlyEnv assigns per-PHP-version FPM/CGI ports is not visible in this file: **UNVERIFIED**.

### 4. Several PHP versions at once
- FlyEnv markets per-project version switching, so it is plausible. How it runs them (one FPM per version, ports) is **UNVERIFIED**. We would design this ourselves anyway: one `php-fpm` (or `php-cgi` on Windows) per version on a fixed port such as 9082 -> 8.2, 9083 -> 8.3, 9084 -> 8.4.

### 5. Hosts file and privileges
- Windows path from `windowsSystemDirectory()\drivers\etc\hosts`. FlyEnv wraps its entries in `#X-HOSTS-BEGIN#` / `#X-HOSTS-END#`, merges via `reconcileSystemHostsBlock`, writes with `writeFileByRoot` only when content changed, then refreshes DNS. Elevation goes through the Go helper (`flyenv-helper`).
- This matches our own block approach (`# >>> hyper-stack >>>`), which is easy to implement ourselves.

## What (ب) means concretely

`hyper` downloads pinned static binaries into `%LOCALAPPDATA%\HyperStack` / `~/Library/Application Support/HyperStack` and manages them itself:

| Component | Candidate source | Notes |
| --- | --- | --- |
| PHP 8.2/8.3/8.4 | static-php-cli builds (or windows.php.net zips on Windows) | Need the Laravel extension set plus redis, gd, intl, zip. Static builds cannot `dl()` extra extensions, so the extension list must be baked per build: **check it covers our needs** |
| Nginx | nginx.org Windows zip; macOS from a static build | Verify arm64 availability |
| MySQL 8 | dev.mysql.com archives (zip on Windows, tar on macOS) | Large download, initialize data dir on first run |
| Redis, Mailpit | Mailpit ships single binaries; Redis on Windows needs a port (e.g. Memurai or tporadowski) | Redis is the awkward one |
| phpMyAdmin | Plain PHP app served by our nginx | |
| Composer, Node 20 | composer.phar, official Node zips | |

Known risks: Windows Redis, PHP static-build extension coverage, MySQL download size/time against the 10-minute goal (consider a mirror on the agency's storage), and code signing for the `hyper` binary.

## Proposed `Runtime` interface changes

Keep the interface, with these edits:

```go
type Runtime interface {
    Name() string
    EnsureInstalled(ctx context.Context, spec StackSpec) error
    EnsurePHP(ctx context.Context, version string, extensions []string) (PHPInstall, error) // PHPInstall carries FPM address
    StartService(ctx context.Context, svc Service) error
    StopService(ctx context.Context, svc Service) error
    ServiceStatus(ctx context.Context, svc Service) (Status, error)
    RegisterSite(ctx context.Context, site Site) error
    UnregisterSite(ctx context.Context, name string) error
    ReloadWeb(ctx context.Context) error   // new: nginx reload after vhost changes
    Paths() RuntimePaths                    // new: data/log/config dirs for doctor and logging
}
```

Additions: `ReloadWeb` (vhost changes need a reload without restart) and `Paths`. `hosts`, `certs`, `envfile` stay outside the runtime as separate packages, since they are runtime-independent. With (ب) the `flyenv` adapter directory is not needed in the MVP; only `internal/runtime/direct`.

## Addendum: official download sources (checked 2026-10-09)

| Component | Windows x64 | macOS (arm64 / x86_64) | Checksum |
| --- | --- | --- | --- |
| PHP 8.2/8.3/8.4 | downloads.php.net/~windows/releases/releases.json lists NTS zips (vs16 for 8.2/8.3, vs17 for 8.4) | dl.static-php.dev `bulk` set, `php-<ver>-fpm-macos-<aarch64\|x86_64>.tar.gz` plus matching `cli` | Windows: sha256 in releases.json. macOS: to be checked |
| MySQL 8.0.x | dev.mysql.com `mysql-8.0.x-winx64.zip` (about 236 MB) | dev.mysql.com macOS tar (URL not yet confirmed) | MD5 only |
| Nginx | nginx.org Windows zip | **No official binary** | n/a |

Findings that change the plan:
1. static-php-cli `common` lacks `intl`; use `bulk` (has intl, opcache, mysqli, sodium, redis, imagick).
2. Windows PHP zips ship intl, gd, zip, mysqli as DLLs to enable in php.ini; **redis is not bundled** on Windows (needs a PECL DLL).
3. nginx.org publishes no macOS binary. Open decision for macOS.
4. MySQL publishes MD5 only, so the manifest must pin it (the installer cannot fetch a signed checksum).
